# VICReg Loss Functions — Anatomy

VICReg prevents representation collapse using three loss terms.
This tutorial breaks down each one using the exact implementations from
[`eb_jepa/losses.py`](https://github.com/Hawar-Dzaee/eb_jepa/blob/main/eb_jepa/losses.py),
then combines them to show how `VICRegLoss` works as a whole.

Every loss below operates on a batch of embeddings $x \in \mathbb{R}^{N \times D}$
where $N$ is the batch size and $D$ is the feature dimension.
In the demos, $D = 2$ so you can see each feature as an axis.

---

## 1. HingeStdLoss

**Goal:** ensure each feature dimension maintains at least a minimum standard
deviation across the batch. If std drops below a margin $\gamma$, a hinge
penalty kicks in. This prevents **point collapse** — the failure mode where
all representations converge to a single constant.

```python
class HingeStdLoss(torch.nn.Module):
    def __init__(self, std_margin: float = 1.0):
        super().__init__()
        self.std_margin = std_margin

    def forward(self, x: torch.Tensor):
        x = x - x.mean(dim=0, keepdim=True)
        std = torch.sqrt(x.var(dim=0) + 0.0001)
        std_loss = torch.mean(F.relu(self.std_margin - std))
        return std_loss
```

**Line by line:**

- `x.var(dim=0)` — variance of each feature across the batch (Bessel-corrected, divides by $N-1$).
- `+ 0.0001` — numerical guard to avoid $\sqrt{0}$.
- `F.relu(self.std_margin - std)` — the hinge: zero when $\text{std} \geq \gamma$,
  positive penalty when below.
- `torch.mean(...)` — average the per-feature penalties into one scalar.

**Try it:** drag the points to collapse them and watch the loss spike.
Use the margin slider to change $\gamma$. Click **Dim 0 only** to see what
happens when just one dimension collapses while the other stays spread.

## 2. CovarianceLoss

**Goal:** penalize off-diagonal elements of the covariance matrix so that
feature dimensions are **decorrelated**. Without this, the encoder can satisfy
variance by spreading along a single direction — all dimensions encode the
same information (dimensional collapse).

```python
class CovarianceLoss(torch.nn.Module):
    def __init__(self):
        super().__init__()

    def off_diagonal(self, x):
        n, m = x.shape
        assert n == m
        return x.flatten()[:-1].view(n - 1, n + 1)[:, 1:].flatten()

    def forward(self, x: torch.Tensor):
        batch_size = x.shape[0]
        x = x - x.mean(dim=0, keepdim=True)
        cov = (x.T @ x) / (batch_size - 1)
        cov_loss = self.off_diagonal(cov).pow(2).mean()
        return cov_loss
```

**Line by line:**

- Center the batch: `x = x - x.mean(dim=0)`.
- Compute the sample covariance matrix: `cov = (x.T @ x) / (N - 1)`.
- `off_diagonal(cov)` — a clever indexing trick that extracts every entry
  *except* the diagonal. For a $D \times D$ matrix, that's $D(D-1)$ elements.
- `.pow(2).mean()` — square each off-diagonal entry and average. The loss is
  zero only when all off-diagonal covariances are zero — i.e., the features
  are uncorrelated.

**Try it:** start with **Correlated** — all points lie near the $y = x$ diagonal,
so $\text{cov}(0,1)$ is large and the loss is high. Click **Decorrelated** and
the off-diagonal drops to near zero.

## 3. Invariance (MSE)

The invariance term is the learning signal — it's not a separate class, just
`F.mse_loss` inside `VICRegLoss`:

```python
sim_loss = F.mse_loss(z1, z2)
```

This is the mean squared error between paired embeddings from two augmented
views of the same image. It pulls view 1 ($\circ$) and view 2 ($\diamond$)
of each sample together. On its own, it collapses everything to a single
point — the cheapest way to make pairs identical is to make *everything*
identical.

---

## 4. VICRegLoss — all three combined

```python
class VICRegLoss(nn.Module):
    def __init__(self, std_coeff=1.0, cov_coeff=1.0):
        super().__init__()
        self.std_coeff = std_coeff
        self.cov_coeff = cov_coeff
        self.std_loss_fn = HingeStdLoss(std_margin=1.0)
        self.cov_loss_fn = CovarianceLoss()

    def forward(self, z1, z2):
        sim_loss = F.mse_loss(z1, z2)
        var_loss = self.std_loss_fn(z1) + self.std_loss_fn(z2)
        cov_loss = self.cov_loss_fn(z1) + self.cov_loss_fn(z2)
        total_loss = sim_loss + self.std_coeff * var_loss + self.cov_coeff * cov_loss
        return {
            "loss": total_loss,
            "invariance_loss": sim_loss,
            "var_loss": var_loss,
            "cov_loss": cov_loss,
        }
```

Note how variance and covariance losses are applied to **each view
independently** then summed — both branches of the encoder must avoid
collapse on their own. The invariance coefficient is implicitly 1;
`std_coeff` and `cov_coeff` are the tunable knobs.

**Try it:** drag circles (z1) and diamonds (z2) to see all three losses
react. Use the coefficient sliders to reweight terms. Click the presets to
see different failure modes:

- **Ideal** — spread, paired, decorrelated. All losses low.
- **Collapsed** — everything at the origin. Variance loss spikes.
- **Correlated** — pairs are close but along a diagonal. Covariance loss spikes.
- **Views apart** — well-spread but pairs are far apart. Invariance loss spikes.

## Key takeaways

- **`HingeStdLoss`** is a *safety net*, not a learning signal. It uses a
  ReLU hinge — once std exceeds the margin, it contributes zero gradient.
- **`CovarianceLoss`** ensures each dimension captures **different**
  information by zeroing out the off-diagonal covariance.
- **Invariance (MSE)** is the *only* term that cares about pairs. It provides
  the training signal; the other two prevent degenerate solutions.
- The `VICRegLoss` class ties them together: `sim + std_coeff * var + cov_coeff * cov`.
