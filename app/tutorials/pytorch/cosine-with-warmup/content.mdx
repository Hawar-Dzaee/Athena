# CosineWithWarmup

Two facts about training drive this schedule. Early on, gradients are noisy — the weights are random, and optimizers like Adam are still estimating their moment statistics — so a full-size learning rate can blow the run up in the first few hundred steps. Late in training, you want the learning rate to glide down smoothly to a small floor so the model settles into a minimum instead of bouncing around it. **Linear warmup** handles the first problem, **cosine annealing** handles the second.

The nice part: PyTorch already ships both pieces, plus a dispatcher that chains them. The whole scheduler is five lines of composition.

## The class

```python
from torch.optim.lr_scheduler import CosineAnnealingLR, LinearLR, SequentialLR

class CosineWithWarmup:
    """Linear warmup to the base LR, then cosine annealing down to min_lr."""

    def __init__(self, optimizer, total_steps, warmup_ratio=0.1, min_lr=1e-5):
        self.optimizer = optimizer
        self.total_steps = total_steps
        self.warmup_steps = int(warmup_ratio * total_steps)
        self.cosine_steps = total_steps - self.warmup_steps

        warmup = LinearLR(
            optimizer, start_factor=1e-8, end_factor=1.0, total_iters=self.warmup_steps
        )
        cosine = CosineAnnealingLR(optimizer, T_max=self.cosine_steps, eta_min=min_lr)

        self.scheduler = SequentialLR(
            optimizer, schedulers=[warmup, cosine], milestones=[self.warmup_steps]
        )

    def step(self):
        self.scheduler.step()

    def get_last_lr(self):
        return self.scheduler.get_last_lr()

    def state_dict(self):
        return self.scheduler.state_dict()

    def load_state_dict(self, state_dict):
        self.scheduler.load_state_dict(state_dict)
```

Everything after `__init__` is delegation: `step`, `get_last_lr`, `state_dict`, and `load_state_dict` all forward to the wrapped `SequentialLR`. To the training loop, `CosineWithWarmup` quacks exactly like a native PyTorch scheduler.
